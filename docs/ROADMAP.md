기록 규칙은 [wiki/schema.md](../wiki/schema.md), ingest 이력은 [wiki/log.md](../wiki/log.md)
에 있다. 이 문서는 **무엇이 아직 안 됐고 다음에 무엇을 하는가**만 적는다.

**아직 아무 데도 배포되지 않았다.** 빌드·설정은 준비됐다 —
`npm run deploy` 한 줄이면 되고, 도메인은 `https://new-ljm.web.app` 이다.
수집 함수 `collectSources` 도 시크릿 없이 배포 가능하다(발굴은 RSS 만 쓴다).
아직 아무도 그 명령을 실행하지 않았을 뿐이다. 수집은 지금까지 전부 로컬에서 수동으로 돌렸다.

**브라우저는 Firebase 를 건드리지 않는다.** 클라이언트 SDK 를 초기화하지 않기로 했다 —
정적 export 에 빌드 타임 Admin SDK 읽기, `firestore.rules` 전면 deny 라 붙일 이유가 없다.
읽는 환경변수의 정본은 `.env.example` 이다.

## 이번 검토에서 고친 것

1. **`wiki:outlets` 이 초안 사건까지 읽었다.** 사람이 검토하지 않은 판정이 위키에
   새어 나갈 수 있었다. 사이트와 같게 `status == "published"` 만 읽는다.
2. **`resolvePoolItem` 의 범위 질의 끝에 U+F8FF 를 문자 그대로 박아 뒀다.** 화면에
   아무것도 안 보여서 빈 범위로 오해하기 딱 좋았다. `String.fromCharCode(0xf8ff)` 로 바꿨다.
3. **프레임이 Firestore 배열 순서대로 화면에 나갔다.** 정성호 사의 사건에서 3건짜리가
   9건짜리보다 앞에 왔다. 큰 묶음부터, 같으면 먼저 나온 기사가 있는 쪽부터 정렬한다.

## 남아 있는 결함

우선순위는 **틀린 사실을 실을 위험**의 크기 순이다.

### 높음

- **'보도하지 않음' 이 질의어에 좌우된다.** 같은 사건·같은 시간창에서 질의어를 바꾸자
  미보도가 6곳 → 0곳이 됐다(2026-07-24 보완수사권 당론). 이 값은 실존 매체에 대한
  사실 주장으로 사이트에 실린다. 지금은 사건 페이지에 각주로만 적혀 있다.
- **매체당 '가장 이른 한 건' 이 불안정하다.** 같은 분에 여러 건을 낸 매체는 재실행 때
  대표 기사가 바뀐다(연합뉴스·뉴시스에서 실제로 발생). 대표가 바뀌면 프레임 배정이
  풀리고 지연 시간도 달라진다.

### 중간

- **발생 시각이 세 사건 모두 추정이다.** 모든 지연 시간이 이 값 하나에 달려 있고,
  한 번은 10시간을 틀려 최초 보도 매체가 미보도로 뒤집힌 적이 있다.
- **프레임 라벨과 경계는 사람 판단이다.** 군집이 여기에 통째로 달려 있다.
  경계를 다르게 그으면 군집도 달라진다. 지금은 그 사실을 적어 두는 것 말고 장치가 없다.
- **제목 변경이 어디에도 안 보인다.** 10건을 관측했는데(한국경제가 같은 날 한 기사는
  「李」→「이 대통령」, 다른 기사는 그 반대로 바꿨다) 사건에 붙은 것만 사건 페이지에
  나오고, 위키에는 전혀 없다. `titleHistory` 는 이 제품의 가장 다투기 어려운 사실이다.

### 낮음

- `next dev` 가 한글 위키 경로를 못 연다. 로컬 확인은 `npm run build` 후 `out/` 을 띄워야 한다.
- 군집 페이지 파일명(`프레임-군집`)이 생성 스크립트와 `src/app/w/page.tsx` 에 따로 하드코딩돼 있다.
- 사건 3은 제목에 위키 인물이 한 명도 없다. 인물 필터를 넓히는 결정이라 검토가 필요하다.

## M1 — 배포 (다음)

지금까지 만든 것을 아무도 볼 수 없다. 이전 위키가 사용자 확보에 실패한 원인을 따지기
전에, 일단 볼 수 있어야 한다.

- [x] 사이트 주소를 `.firebaserc` 에서 끌어오게 했다. 지금까지 OG·공유 카드 URL 이
      전부 `example.com` 이었다.
- [x] `/method` 와 사건 페이지에 **'보도하지 않음' 은 검색어에 달린 값**임을 실측 수치와
      함께 적었다. 이건 배포의 전제 조건이었다 — 실존 매체에 대한 사실 주장을 근거 없이
      내보낼 수 없다.
- [x] 배포 스크립트 (`npm run deploy`, `deploy:functions`, `deploy:rules`)
- [ ] **`npm run deploy` 실행** (사람이 해야 한다 — 외부로 나가는 작업이다)
- [ ] `npm run deploy:rules` — Firestore 규칙(전면 deny)을 실제로 반영
- [ ] `npm --prefix functions run deploy` — `collectSources` 스케줄 함수

**완료 조건** `https://new-ljm.web.app` 에서 사건 3건과 위키가 보이고,
수집이 사람 손 없이 하루 4회 돈다.

## M2 — 판정 신뢰도 ✅

M1 의 각주를 장치로 바꿨다.

- [x] `curate compare <id> "<질의어1>" "<질의어2>" [시간]` — 검색어를 바꿔 가며
      **잘못된 '보도하지 않음'** 을 찾는다. 너무 좁은 질의어는 따로 경고한다.
- [x] `curate silent <id> [시간]` — 미보도 매체의 기사가 우리 저장소에 있는지 훑는다.
      자동으로 붙이지 않는다 — 제목이 겹친다고 같은 사건이라는 보장이 없다.
      호스트를 함께 찍는다(MBN 을 매일경제로 붙일 뻔한 뒤에 넣었다).
- [x] 대표 기사 선정 안정화 — 같은 시각이면 URL 로 결정적 정렬
- [x] `CoverageEntry.reason` — '검색이 못 찾음' 과 '사람이 뺌' 을 구분한다.
      구분하지 않으면 `compare` 가 운영자의 판단을 매번 뒤집으라고 한다.

**완료** 세 사건 모두 검색어를 바꿔도 '보도하지 않음' 이 뒤집히지 않는다.
[[outlets/donga]] 의 잘못된 미보도 1건을 이 과정에서 찾아 고쳤다.

**남긴 것** — `reason` 을 화면에 쓰지 않는다. 사건 페이지는 '검색이 못 찾음' 과
'운영자가 제외함' 을 여전히 한 덩어리로 보여준다. 위키 사건 페이지에는 글로 구분돼
있지만 사이트에는 없다. 둘은 다른 주장이므로 나눠 보이는 편이 옳다.

## M3 — 축적, 그리고 군집이 뜻을 갖는 지점

지금 군집의 최대 근거는 3/3 한 쌍이다. 사건 3건은 아무것도 증명하지 못한다.

- [x] **인물 페이지의 집계를 스크립트로 내렸다** (`wiki:people`). 버티지 못한다는 게
      확인됐다 — 페이지의 40~65% 가 산수였고 사건 하나에 7개 파일의 숫자를 짝 맞춰
      고쳐야 했다. 이제 `<!-- generated:events -->` 표시 구간만 스크립트가 쓰고,
      발언 인용·등장 방식 서술 같은 판단은 사람이 쓴다.
      별칭(「李」가 누구인지)은 각 인물 페이지가 선언한다 — 기계가 판단할 수 없다.
- [ ] 사건 10건 (지금 3건)
- [ ] 사건 수가 늘 때 군집이 어떻게 변하는지 기록 (2건 → 5곳 군집, 3건 → 6곳+2곳으로
      갈라진 것처럼)

**완료 조건** 사건 5건 이상에서도 살아남는 완전 일치 쌍이 있는가 없는가에 답할 수 있다.

**이 과정에서 찾은 것** — 같은 「李」가 두 코드포인트로 온다. U+674E(동아일보)와
U+F9E1(조선일보·이데일리 등 CJK 호환 한자). 한국 언론사 편집 시스템이 호환 한자를
그대로 내보낸다. 정규화하지 않으니 이재명 등장이 20건이어야 할 자리에 13건으로
나왔다. 비교할 때만 NFC 로 정규화한다 — 저장된 제목은 원문 그대로 두어야 한다.

## M4 — 제목 변경

이 제품에서 가장 다투기 어려운 사실인데 지금 아무 데도 안 보인다.

- [ ] 기존 항목을 재조회해 제목 변경을 계속 관측하는 작업 (설계서 211행에 적혀만 있다)
- [ ] 변경 이력을 위키에 생성 페이지로 뽑는다 (매체 페이지·군집 페이지와 같은 방식)
- [ ] 이재명 필터를 통과한 것만 — 지금 관측된 10건 중 3건이 해당한다

**완료 조건** 「이 기사는 게시 N분 뒤 제목을 바꿨다」가 매체 페이지에 남는다.

## 하지 않기로 한 것

- **유튜브 채널 추가.** 미보도 지표가 깨지고, 채널 선정에 중립적 기준이 없으며,
  개인에 가까워 명예훼손 노출이 커진다. 판단 근거는 DESIGN.md 참조.
- **웹 admin.** 하루 1~3건에 UI 는 과잉이고 정적 사이트에 인증 화면은 공격 표면이다.
- **매체 성향·등급 라벨.** 고정 라벨은 낙인이 된다. 분류는 사건 단위 프레임으로만 존재한다.
