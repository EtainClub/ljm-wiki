## 채널을 추가하는 법

2026-10-03에 관련 보도·논평을 반복적으로 다루는 채널 16곳을 조사·등록했다.
고유 ID·영상 사례·보류 사유는 [채널 조사 기록](YOUTUBE-CHANNELS.md)에 남겼다.
`npm --prefix functions run youtube:review -- <@핸들 또는 UC ID...>`로 등록 전
최근 제목을 읽기 전용으로 확인할 수 있다. 후보 수는 사람의 관련성 검토를 대신하지 않는다.

채널 ID를 미리 찾을 필요가 없다. `@핸들`, `https://www.youtube.com/@핸들` 주소,
또는 `UC`로 시작하는 채널 ID를 입력하면 등록 명령이 YouTube API로 실제 채널과
업로드 재생목록을 확인한다. 이름이 비슷한 채널을 검색으로 골라 넣지는 않는다.

```bash
YOUTUBE_API_KEY=... npm --prefix functions run youtube:add -- "표시할 채널명" "@채널핸들" 100
```

예를 들어 `https://www.youtube.com/@parksiyoungTV`는 다음처럼 등록한다.

```bash
npm --prefix functions run youtube:add -- "박시영TV" "@parksiyoungTV" 100
```

명령이 출력하는 실제 YouTube 채널명과 채널 ID가 의도한 대상인지 확인한다. 이 명령은
한 번만 `channels.list`로 업로드 플레이리스트를 확인한다. 이후 수집기는 그
플레이리스트만 읽는다. 등록 뒤에는 다음을 설정하고 함수를 재배포한다.

```bash
firebase functions:secrets:set YOUTUBE_API_KEY
npm --prefix functions run deploy
```

`YOUTUBE_API_KEY`는 YouTube Data API용 키이며 AI 모델 API가 아니다.

## 화면과 분석의 한계

- `/youtube` 상단의 최근 영상은 서버가 활성 등록 채널의 최근 7일 수집 제목을 읽는다.
  채널당 최신 25건을 조회하며, 명시된 이재명·이 대통령·李대통령 제목과 유효한
  YouTube 원문 링크만 표시한다. 이재명 의사 등 동명이인 제목은 제외한다.
  삭제 상태와 미발행 사건에 배정된 항목은 제외하며, 화면은 최신 20건을 보여준다.
  원제·채널·게시 시각만 표시하고 수집 제목을 영상 내용 요약으로 쓰지 않는다.

- `/youtube`에서 공개 사건에 연결된 영상들을 채널·사건·제목 검색으로 탐색한다.
  같은 사건의 원제·제목 프레임·변경 이력을 비교하며 영상 0건은 미보도 판정으로 쓰지 않는다.
- 질문부호·인용부호·라이브·쇼츠 표기는 제목에서 관찰한 형식이다. 실제 영상 장르나
  정치적 찬반 태도를 자동으로 판정하지 않는다.
- 사건 요약은 사건 맥락으로 표시한다. 현재 영상 내용 요약으로 재사용하지 않는다.

- 사건 프레임 안에서 `언론 기사`와 `유튜브 영상`을 별도 묶음으로 보인다.
- 유튜브 채널은 네이버 기사 검색의 대상이 아니므로 `보도하지 않음` 목록에 넣지
  않는다. 수집된 영상 제목이 사건과 직접 관련될 때만 해당 프레임에 표시한다.
- 발행 뒤 영상이 발견되면 `curate correct-youtube <사건ID>`가 사건 제목의 마지막
  핵심어를 반드시 포함하고 전체 핵심어 중 두 개 이상이 영상 제목에 있으며, 사건
  24시간 전~48시간 후에 게시된 영상만 정정
  계획으로 저장한다. 이 단계에서는 공개 사건을 바꾸지 않는다.
- 사건 제목이 '주문'·'언급'처럼 영상 제목에 나오지 않는 낱말로 끝나면 자동 규칙은 영상을
  찾지 못한다. 그때는 `curate correct-youtube <사건ID> "<필수어>" "<핵심어,...>" <최소개수>`로
  영상 제목에 실제로 쓰인 낱말을 규칙으로 준다. 이 규칙도 사건 화면에 그대로 공개된다.
- 발행 전에는 `curate videos <사건ID> "<핵심어,...>"`로 사건 창(24시간 전~48시간 후)의 등록
  채널 영상 후보를 본다. `curate list`는 최근 500건만 보므로 지난 날짜 영상이 빠진다.
- 이어 `queue:approval -- correction <사건ID>`로 만든 PR을 병합해야만 같은 사건 URL에
  영상·연결 규칙·정정 시각이 적용된다. 한 채널의 여러 영상은 모두 보존한다.
- 이 자동 연결은 제목과 게시 시각만 근거로 한다. 연결된 영상은 '보도함' 또는
  '미보도' 판정에 섞지 않으며, 영상 내용·의도에 관한 판단도 아니다.
- 아직 발행하지 않은 사건에서 제목으로 직접 관련성을 확인한 영상은
  `curate attach-youtube <사건ID> <영상ID...>`로 붙인 뒤 별도 프레임에 배정한다.
  같은 채널의 여러 영상도 허용하며, 이 명령은 언론의 '보도함/미보도' 집계에
  영향을 주지 않는다.
- 프레임은 제목이 무엇을 앞세우는지만 서술한다. 예: `'의혹 제기'를 앞세움`.
- 영상의 발언, 자동 자막, 썸네일 문구, 제작 의도는 현재 분석 대상이 아니다.
- 따라서 특정 채널이 어떤 정치인을 지지하는 척한다거나 비방한다는 식의 라벨을
  붙이지 않는다. 그런 주장은 제목만으로 확인할 수 없다.

YouTube API의 자막 접근은 OAuth 권한을 요구하며, 제3자 영상의 자막·영상 수집과
교차 채널 API 데이터 집계에는 별도 정책 제한이 있다. 내용 기반 분석을 공개하려면
채널의 허가된 전사본 또는 별도 라이선스·약관 검토 경로를 먼저 마련해야 한다.
